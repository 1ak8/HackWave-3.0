PAGE 1: AUDIT TRAIL (/audit)
================================================================================

1. ASLI DUNIYA KA EXAMPLE (THE ANALOGY):
--------------------------------------------------------------------------------
Jab koi commercial aeroplane udta hai, toh flight ke andar ek "Black Box" (Flight 
Data Recorder) laga hota hai. Yeh Black Box flight ke har ek second ka record 
rakhta hai—pilot ne steering kab ghumaayi, engine ka pressure kitna tha, altitude 
kya thi. Agar koi gadbad hoti hai ya inspection karni hoti hai, toh aviation 
authorities sabse pehle Black Box ko check karti hain.

Theek waise hi, AUDIT TRAIL hamare AI Testing Engine ka "Black Box" hai!


2. YEH PAGE KYUN HAI? (THE BIG ENTERPRISE PROBLEM):
--------------------------------------------------------------------------------
Maan lo tum Amazon, Swiggy, Paytm ya Netflix ke Engineering Director ho.
Agar koi vendor tumhein bole: "Humara AI tool tumhare tests ke toote huye buttons 
ko background mein khud hi repair karke tests pass kara dega."

Toh tumhara sabse pehla sawaal hoga:
  "Bhai, AI ne mere code mein apne man se kya change kiya?
   Kaunse button ko replace kiya? Kyun kiya?
   Kahin AI ne kisi asli fatal bug ko daba kar zabardasti test ko pass toh nahi kar diya?"

Bina 100% PROOF, VERIFICATION aur AUDIT RECORD ke koi bhi enterprise company kisi 
bhi AI tool ko apne deployment pipeline mein allow nahi karegi. Audit Trail wahi 
bulletproof trust aur compliance layer provide karta hai.


3. STEP-BY-STEP RECORD MEIN KYA-KYA SAVE HOTA HAI?
--------------------------------------------------------------------------------
Jab bhi koi test chalta hai aur koi button heal hota hai ya koi bug pakda jata hai, 
toh database (aur disk storage) mein uska ek permanent, immutable record create 
ho jata hai:

  [A] Exact Timestamp & Run ID:
      - Har action ka exact time (e.g. 01:41:19 AM) aur Run Reference ID save hota hai.
      - Manager dekh sakta hai ki yeh kis execution run mein hua tha.

  [B] Step Name & User Goal (Intent):
      - E.g. Step #1 — Select Product (User Goal: "Add headphones to shopping bag").

  [C] Code Transformation (Red vs Green Diff):
      - Broken Selector (Red):   - #btn-add-to-cart (Frontend developer ne rename kar diya tha)
      - Healed Selector (Green): + #dynamic_btn_cart_x89 (AI ne naya button detect karke replace kiya)

  [D] AI Match Confidence Score:
      - E.g. "99% Verified Match". Engine accessibility tree aur semantic intent 
        ko score karke confidence calculate karta hai.

  [E] AI Natural Language Reasoning (Pura Explanation):
      - AI paragraph likhkar reason deta hai:
        "Original selector #btn-add-to-cart missing in DOM due to redesign. Located 
        dynamic replacement <button> with label 'Claim Headphones Now' satisfying 
        the business intent 'Add headphones to bag'."

  [F] Smart Triage Bug Record (Sabse Bada Proof):
      - Agar application mein asli software bug aaya (jaise payment 500 error):
        Status: GENUINE REGRESSION • HEALING REFUSED
        Reason: "Critical Application Bug detected: Payment gateway returned HTTP 500 
        and cart total was corrupted ($0.00). AI verified this is a genuine software 
        defect, NOT a cosmetic UI rename. Healing safely aborted to protect production!"


4. IS PAGE PAR CONTROLS & FEATURES:
--------------------------------------------------------------------------------
  - 3 Summary KPI Cards:
      * Mutations Repaired (Harmless UI shifts healed)
      * Regressions Blocked (Smart Triage prevented false test passing)
      * Average Match Confidence (Verified AI precision score)
  - Scannable Enterprise Table View (Default):
      * Har record ek clean 1-line row mein dikhta hai with time, step, selector 
        diff arrow, status badge, aur confidence.
      * Row par click karte hi smooth inline drawer khulta hai jisme pura AI 
        reasoning breakdown aur raw technical parameters dikhte hain.
  - View Switcher: Table View [ 📋 ] aur Compact Card Feed [ 🗂️ ] ke beech toggle.
  - Live Search Bar: Step name, selector ID, ya intent text se instant filter.
  - 1-Click Filter Tabs: ALL, Auto-Healed, Bugs Triaged.
  - Export JSON Button: 1-click mein pura SOC-2 compliance audit log JSON file mein download karo!

PAGE 2: DEMO STORE (/demo-store)
================================================================================

1. ASLI DUNIYA KA EXAMPLE (THE ANALOGY):
--------------------------------------------------------------------------------
Car companies jab naya airbag ya braking system banati hain, toh wo car ko 
seedha market mein nahi bechti. Wo pehle ek dedicated "Crash Test Arena" mein car ko 
deewar par thok kar dekhti hain ki crash ke waqt safety features activate hote hain ya nahi.

Theek waise hi, DEMO STORE hamara Live Testing Ground & Crash Test Arena hai!
Yahan judges aur users apni aankhon se dekh sakte hain ki jab frontend tootta hai, 
toh AI use live kaise fix karta hai.


2. DUAL-PANE SPLIT DESIGN (ZERO REDIRECT):
--------------------------------------------------------------------------------
Pura testing arena ek hi screen par side-by-side banta hai (koi doosre page par jane ki zaroorat nahi):

  [LEFT PANE — 60% Width]: Live E-Commerce Sandbox Store
  - Real 3-step online store workflow:
    1. Product Page: Quantum Wireless Headphones ($149.00)
    2. Checkout Drawer: Customer Email & Shipping Address form
    3. Order Confirmation: Fulfillment tracking screen (#order-success-badge)
  - Har button aur input field ke niche uska live DOM selector ID saaf visible rehta hai.

  [RIGHT PANE — 40% Width]: Real-Time Autonomous Inspector Panel
  - Tab 1: Live Test Pipeline & AI Diff
    * Steps ka live status update: Waiting... ➔ AI HEALING... ➔ AUTO-HEALED ya PASSED.
    * Real selector diff box: - Broken vs + Healed (sirf tab jab selector mutate hua ho).
  - Tab 2: Real-Time Playwright Telemetry Logs
    * macOS style dark terminal jahan live timestamps ke sath INFO, WARN, HEAL, 
      PASS, FAIL logs real time mein stream hote hain.


3. THE 4 DEMO MODES (AND WHAT THEY PROVE):
--------------------------------------------------------------------------------
Top bar par 4 tabs hain jo engine ki alag-alag capabilities prove karte hain:

  [A] Version A (Standard Baseline):
      - Store ka normal code bina kisi mutation ke.
      - User click kare ya bot chalaye, saare 6 steps direct baseline selectors par pass hote hain.

  [B] Version B (Realistic Release & Auto-Heal):
      - Real-world release simulate karta hai jahan developers ne 3 selectors rename 
        kar diye (#btn-add-to-cart, #input-checkout-email, #btn-complete-order) jabki 
        3 selectors unchanged chhod diye.
      - AI 850ms deliberate karta hai, accessibility tree scan karta hai, aur mutated 
        selectors ko heal karta hai jabki normal steps direct pass hote hain.

  [C] Live Chaos Mode (Judge's Custom Control Deck):
      - Top par centered segmented pill capsule dock:
        [ 1. Cart ⚡ ]  [ 2. Bag ]  [ 3. Email ⚡ ]  [ 4. Address ]  [ 5. Pay ⚡ ]
      - Judge jo toggle ON karega, SIRF WAHI STEP mutate aur heal hoga!
      - Untoggled steps Version A ki tarah direct pass honge.
      - Yeh judge ko 100% control deta hai to test any permutation live!

  [D] Real Bug Mode (Smart Triage in Action):
      - Steps 1 aur 3 harmlessly auto-heal hote hain.
      - Lekin Step 5 par $0.00 pricing corruption aur HTTP 500 payment crash trigger hota hai.
      - AI halts execution immediately with "BUG HALTED (Genuine_Bug_Halted)"!
      - AI refuses to heal because it's a real server crash, not a selector change.


4. MANUAL CLICKS VS "AUTO-RUN E2E BOT":
--------------------------------------------------------------------------------
Demo Store mein do tareeqe hain test run karne ke:
  1. User Manual Clicks:
     - User khud left store mein "Add to Bag", drawer open, form fill aur payment click karta hai.
     - Har click ke sath right pane mein live pipeline update hoti hai aur 
       terminal mein real-time logs stream hote hain.
  2. Auto-Run E2E Bot (Playwright Robot):
     - Top bar par button hai: [ ⚡ Auto-Run E2E Bot ].
     - Headless Playwright robot background mein chalta hai aur user apni aankhon 
       se dekhta hai ki left store ke buttons auto-click ho rahe hain, fields fill 
       ho rahi hain, aur right panel sync ho raha hai!

PAGE 3: TEST STUDIO (/studio)
================================================================================

1. ASLI DUNIYA KA EXAMPLE (THE ANALOGY):
--------------------------------------------------------------------------------
Jab tum Uber book karte ho, toh tum driver ko yeh nahi bolte:
  "Pehle clutch dabao, fir pehla gear lagao, 20 meter baad 15 degree steering modna..."
Tum use seedha apna Destination / GOAL (Intent) bolte ho:
  "Bhai, mujhe Airport le chalo!" Driver rasta khud dhoond leta hai.

Traditional testing tools (Cypress/Selenium) pehle wale tareeqe par chalte hain—
har ek button ka hardcoded CSS selector likhna padta hai.
TEST STUDIO doosre tareeqe par chalta hai—yahan tum USER GOAL define karte ho, 
aur engine baki sab khud handle karta hai!


2. YEH PAGE KYUN HAI? (THE 50% MAINTENANCE PAIN):
--------------------------------------------------------------------------------
Har software team mein frontend developers roz buttons ke class names, IDs aur 
design badalte hain. Har deployment par 30-40% purane Cypress/Playwright tests fail 
ho jaate hain. QA engineers ka aadhe se zyada din code test karne mein nahi, balki 
purane toote huye selectors ko manually update karne mein waste ho jata hai.

Test Studio is selector maintenance overhead ko poori tarah khatam karta hai!


3. STEP-BY-STEP KAAM KAISE KARTA HAI?
--------------------------------------------------------------------------------
Yahan koi bhi (QA tester, Developer, ya non-tech Product Manager) bina code 
likhe naya test case create kar sakta hai:

  [A] Suite Title & Target Endpoint:
      - E.g. "VIP Subscription Checkout Flow" -> Target: http://localhost:5173/demo-store

  [B] Business Outcome / Main Intent:
      - User outcome: "Complete hardware package purchase with verified shipping and payment."

  [C] Dynamic Multi-Action Step Builder:
      - Step 1: Action: Click  • Intent: "Add headphones to shopping bag" • Hint: #btn-add-to-cart
      - Step 2: Action: Click  • Intent: "Open checkout side drawer"      • Hint: #btn-view-cart
      - Step 3: Action: Fill   • Intent: "Provide verified buyer email"    • Value: user@test.com
      - Step 4: Action: Click  • Intent: "Submit order & charge payment"   • Hint: #btn-complete-order
      - Step 5: Action: Assert • Intent: "Verify fulfillment confirmation screen"

  [D] Baseline Hint vs Auto-Heal:
      - Jo selector tum likhte ho, wo sirf ek initial starting hint hai.
      - Agar future mein developer ne use badal diya, toh engine tumhare 
        likhe huye INTENT ko padhkar naya button khud dhoond kar test pass kara lega!

  [E] 1-Click "Run & Inspect":
      - Right panel par Configured Suites ki list aati hai.
      - Kisi bhi suite ke aage "Run & Inspect" button dabate hi spinner aata hai, 
        aur page turant Live Test Runner (/live) par redirect hota hai jahan live 
        graph aur terminal output stream hota hai!

2. MISSION CONTROL KA DUAL-PANE LAYOUT:
--------------------------------------------------------------------------------
Screen do powerful interconnected sections mein bati huyi hai:

  [SECTION 1: THE INTERACTIVE INTENT GRAPH (UPAR)]
  - Pure test ke steps visual squircle node cards ke form mein aate hain.
  - Har step live execution ke sath color badalta hai:
    * Blue Pulse: Step actively running in browser
    * Amber Spinner: Selector broke! AI is currently healing...
    * Emerald Sparkles: AUTO-HEALED with match confidence score!
    * Green Check: PASSED directly on baseline selector (No AI needed)
    * Red Shield: REAL BUG TRIAGED — Execution halted to protect production!
  - Kisi bhi node par click karte hi niche uska deep inspection khul jata hai.

  [SECTION 2: DUAL SPLIT INSPECTOR (NICHE)]
  - Left Side: GitHub-Style Diff Inspector
    * Shows Step #, Action type, and User Goal.
    * Sleek Red/Green code diff:
      - Broken:   #input-checkout-email (Missing in DOM)
      + Healed:   #customer_email_contact (99% Match Verified)

      jisse tum bina upar jaaye card ke andar hi ek-ek step ka diff inspect kar sakte ho!
  - Right Side: Playwright Telemetry Stream Terminal
    * macOS style dark terminal (#0f172a) with live timestamps.
    * Live socket events stream hote hain: INFO, WARN, HEAL, PASS, FAIL.

      - Isko ON karke jab tum "Auto-Heal Run" ya "Standard" click karte ho,

        * Browser demo store kholta hai.
        * Buttons par click karta hai.
        * Forms type karta hai.
        * Mutated selectors ke naye buttons AI dhoond kar click karta hai!
      - Test pass hone ke baad window 2.5 second rukti hai taaki tum confirmation screen dekh sako.
