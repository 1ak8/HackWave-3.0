============================================================
   SELF-HEALING SOFTWARE TESTS — UNIQUE FEATURES
   Intent-Aware E2E Testing That Survives UI Changes
============================================================

PROBLEM STATEMENT:
Traditional E2E tests break when a button is renamed, moved,
or redesigned — even when the user workflow still works.
Teams waste hours fixing selectors instead of testing behavior.

OUR SOLUTION:
A testing system that understands the INTENT of a test,
not fixed selectors. It interprets the current UI, finds
the right actions, and heals itself when things change.

FEATURE 3: HARMLESS vs REAL FAILURE — Smart Triage
------------------------------------------------------------

Kya Hai:
AI sirf heal nahi karta, JUDGE bhi karta hai ki change
harmless hai ya real application bug hai.

Kaise Kaam Karega:

Scenario A — Button Rename (HARMLESS):
  "Buy Now" → "Purchase"
  AI: "GREEN: Harmless rename. Same function. Auto-healing."

Scenario B — Button Moved (HARMLESS):
  Checkout button top → bottom
  AI: "GREEN: Design change. Same functionality. Healing."

Scenario C — Price Shows $0 (REAL BUG!):
  Cart total: $149 → $0
  AI: "RED: REAL FAILURE. Cart total is $0. This is a BUG.
       DO NOT HEAL. Alerting developer. Test correctly FAILED."

Scenario D — Pay Button Missing (REAL BUG!):
  Pay button completely removed from DOM
  AI: "RED: REAL FAILURE. Payment button gone. Possible
       deployment error. NOT healing. Escalating to team."
